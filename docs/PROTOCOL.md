# 创意工坊协议 v1

## 1. 作品 ID 与条目命名

作品 ID 只能包含英文字母、数字、点、下划线和连字符，长度为 3～64 个字符，例如：

```text
nkashei.weather-story
```

兼容扩展创建的世界书条目应使用以下前缀，防止与本体或其他扩展重名：

```text
[jmzq_ext:nkashei.weather-story] 条目名称
```

## 2. MVU 状态

本体 ZOD 预留了以下公共容器：

```text
工坊扩展.<作品ID>.启用
工坊扩展.<作品ID>.版本
工坊扩展.<作品ID>.数据
```

兼容扩展只能写入自己的 `数据`。关闭扩展时保留数据，只停止其世界书条目路由。

## 3. 世界书注册表

安装器在当前角色绑定的世界书中维护一个禁用且不会进入提示词的条目：

```text
[jmzq_workshop]扩展注册表
```

条目正文为 JSON：

```json
{
  "protocolVersion": 1,
  "packages": [
    {
      "id": "nkashei.weather-story",
      "name": "天气故事扩展",
      "version": "1.0.0",
      "enabled": true,
      "entries": [
        {
          "name": "[jmzq_ext:nkashei.weather-story] 暴雨求生",
          "enabledByDefault": false,
          "activeWhen": {
            "all": [
              { "path": ["世界阶段"], "operator": "in", "value": ["爆发期", "末世期"] },
              { "path": ["环境", "天气"], "operator": "contains", "value": "暴雨" }
            ]
          }
        }
      ]
    }
  ]
}
```

注册表跟随世界书迁移。浏览器本地存储只保存界面偏好和人工启停偏差，不作为扩展安装事实来源。

## 4. 声明式条件

组合条件支持：

- `all`：所有子条件成立；
- `any`：任一子条件成立；
- `not`：子条件不成立。

叶子条件包含 `path`、`operator` 和可选的 `value`。路径优先使用字符串数组，避免字段名中的点产生歧义。

支持的操作符：

| 操作符 | 含义 |
|---|---|
| `eq` / `neq` | 严格相等 / 不等 |
| `gt` / `gte` / `lt` / `lte` | 数值比较 |
| `in` / `not_in` | 值是否位于数组中 |
| `contains` | 字符串包含文字，或数组包含值 |
| `starts_with` / `ends_with` | 字符串前缀 / 后缀 |
| `exists` | 路径是否存在；`value:false` 表示不存在 |
| `truthy` / `falsy` | 真值 / 假值 |

协议不支持表达式求值、函数或正则表达式，避免扩展借绑定规则执行任意代码。

## 5. 人工偏差

小助手自动路由扩展条目后会保存启用快照。玩家手动改变条目时，小助手保留人工状态并提示偏差；只有玩家点击“同步预设机制”才恢复扩展作者的规则。

## 6. 深度改造

深度改造不写入上述自动注册表。后续安装指导需要记录：

- 适配的本体版本；
- 被替换组件及原始文件指纹；
- 安装顺序和依赖；
- 与其他深度改造的冲突；
- 备份和卸载步骤；
- 修改后的完整文件或人工替换说明。
